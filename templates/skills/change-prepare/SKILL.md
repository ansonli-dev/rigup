# Prepare a change

1. **Start the native workflow.** Open [project context](references/project.md) and use the installed preparation entry or listed customer skill. For OpenSpec, use the prepare entry for a new proposal and the revision entry for an active change. Follow its prerequisites and load its context before discovery. If a required entry or workflow root is unavailable, identify the missing prerequisite and stop.
2. **Scope the change.** At the workflow's inspection step, start from the requested outcome and likely paths. Use targeted path or symbol searches, then read the nearest implementation and test. Before proposing an edit to a request type, validator, or reusable helper, search its references and check consumers outside the requested scope. If a shared edit would affect those consumers, plan the change at the boundary that owns the requested behavior. Use the project development rules index to open only topics that match the touched paths or behavior. Read their relevant sections and applicable exceptions. Batch independent reads and reuse findings across artifacts. Finish discovery once the boundary, applicable rules and acceptance criteria are clear. Clarify material ambiguity and carry unresolved conflicts forward as decisions.
3. **Choose verification.** Name the closest existing test to extend or run, and use the project check entries to record its command and working directory. Add checks required by the change or workflow. Inspect a hook or CI definition when the plan relies on it and record any coverage gap.
4. **Write and hand off.** Follow the native artifact instructions and dependency order. Keep work within authorized operations, the budget and the planning boundary, observing native human approval gates at each step. Record the expected behavior, boundary, applicable rules and checks in the native artifacts. Check native readiness and record any omission the native instructions explicitly allow. Hand off the change identifier, artifacts, scope, check commands, open decisions and next workflow action. Wait for the required approval or separate implementation request.
