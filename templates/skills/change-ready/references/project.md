# Project context for readiness

Use the installed native workflow to locate the exact change, every current planning artifact and its prerequisites. Read the native status and instructions; never infer readiness from the presence of a task file alone. Preserve required human approval gates.

Use **Existing checks** to validate commands and their working directories, without running setup or changing files. Follow original guidance and confirmed **Team conventions** for the affected paths. Check that implementation tasks and observable verification cover every material acceptance criterion in the GOAL and native Spec.

For a selected customer workflow, inspect both its preparation and delivery entries and retain its prerequisite and approval rules. The readiness report does not create an approval or change task state.
