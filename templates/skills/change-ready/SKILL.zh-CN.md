# 检查实施是否就绪

此步骤仅做只读审阅。保持产出物、源代码、测试、任务状态、配置和批准记录原样。在审阅预算内完成检查，依赖安装和会修改状态的检查留待实施。

项目上下文如果指定了 OpenSpec CLI 的调用方式，请在执行原生步骤和下列命令时使用它。

1. 阅读[项目上下文](references/project.md)、该变更的 `GOAL.md` 和所选的原生工作流入口。确认准确的变更 ID、修订版本和已审阅的写入范围。按每份文件所在位置解析 GOAL、Spec 和 Plan 的全部引用，包括拆分的产出物。检查每个文件都存在于仓库内、属于当前同一变更，并反映最新修订。指向其他变更的链接属于阻塞项。检查适用的原始指南和每个已安装入口的前置条件。
   - 将计划的全部写入与 **Reviewed write scope** 核对，包括业务文件、适用的原生任务勾选项或状态，以及证据和记录位置。交付要修改的每个文件及其允许用途都须明确列出。GOAL 本身只有在特定记录写入已经过明确审阅时才可写入。旧版 GOAL 只要包含等效而完整的范围和证据即可接受，允许沿用原有格式。发现遗漏时，给出该文件的仓库相对路径，包括预期更新的任务文件。阻止就绪并交回 change-prepare，接受范围审阅与批准。
2. 阅读原生就绪证据。对于 OpenSpec，从项目根目录运行 `openspec list --json`、`openspec status --change <id> --json` 和 `openspec instructions apply --change <id> --json`。以原生状态和指令为准。`isPlanningComplete: false`、非空的 `missingPrerequisites`、受阻的 apply 状态或尚未完成的必需产出物都会阻止就绪。原生工作流要求的 `design.md` 必须完成，即便负责准备的智能体曾将其标为可选。其他工作流按已安装的前置条件命令和人工批准门槛执行。核实所有必需批准，包括对当前已审阅变更、修订版本与范围的明确人工实施批准。批准须来自当前人工指令，或适用且经过验证的项目指定记录。若当前人工指令明确更新同一修订版本与范围的批准状态，以新指令为准。实施批准缺失、待定、过期或范围不符时，即便原生规划已完成，仍应阻止就绪。批准证据冲突时，交由批准者确认。此检查只验证批准。
   - 批准必须覆盖完整的已审阅写入范围。任何遗漏、指向另一修订版本或范围不一致都将阻止就绪。若完整当前范围已获明确批准，额外授权的路径和操作可同时存在。列出这些未使用的授权，交付仅使用已审阅的范围。计划但遗漏的路径仍须补审。需要改变范围时回到准备、审阅和批准。批准覆盖范围有歧义时，由批准者确认。当前批准可以取代旧的待批准状态，保留 GOAL 和批准记录原样。
3. 将每项重要验收标准对应到具体的原生实施任务和验证方法，涵盖拒绝场景与应保留的行为。根据项目指南核实命令和工作目录，确认每项标准都有可观察的通过条件及证据写入位置。诸如“一切正常”的模糊目标、缺少的验收验证、过期的任务、不可用的原生入口或未经审阅的范围变动都将阻止就绪。
4. 检查 GOAL 是否链接已安装的[交付技能](../change-deliver/SKILL.md)、适用的项目指南和所选原生实施入口。提交、推送或 MR 跟进如果纳入范围，请确认相应的授权、平台、项目以及现有工具、检查和审阅者配置。如实记录缺少的目标位置或前置条件。
5. 受阻时，报告涉及的文件、未满足的标准、原生前置条件或批准缺口，以及具体的纠正步骤。交回 [change-prepare](../change-prepare/SKILL.md) 或批准者，并请开发者随后重跑 change-ready。此时保留受阻结论，暂缓输出 **Ready for implementation** 及任何可执行的实施命令，包括 `/goal` 和兼容交付命令。
6. 全部标准满足后，逐字报告 **Ready for implementation**，并给出下面可复制的命令。把路径替换为实际的仓库相对 GOAL 路径：

   `/goal Implement the reviewed change in "<actual-repository-relative-path>/GOAL.md" and verify every completion criterion in that file.`

开发者随后提交这条准确的 `/goal` 命令，才会启动已经过批准的范围。缺少的批准和额外原生前置条件仍须补齐。范围变动后需要重新审阅和批准。不支持 `/goal` 的宿主使用 change-deliver，沿用同一个 GOAL 和同一批批准。

这些技能为加载它们的智能体提供操作指引。宿主权限负责控制文件系统访问；技能本身无法在遭绕过时强制限制写入。无论请求的紧急程度，加载此技能后仍须满足所有前置条件。
