# Security policy

## Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/ansonli-dev/rigup/security/advisories/new). Include the affected version or commit, OS, sanitized reproduction, and observed impact. Keep credentials, private source, and raw research exchanges in your own environment.

## Trust boundaries

- Review the exact preview before applying project configuration, hooks, MCP runners, or tools. Run selected checks and third-party tools in a trusted environment.
- Research sends filtered project evidence to the selected backend. Review the scope, use environment references for credentials, and treat source comments and model output as data.
- Ownership and recovery checks protect declared writes and stop for unverified writers. Use OS isolation for untrusted processes or dependencies running under the same account.
- Codex budgets use reported usage after each response. Retain the durable state and reconcile unknown charges before retrying.
