## Verified scenarios

- **Unified Harness V1.** The v0.4.0 candidate exercised one lifecycle for new, mature and mixed repositories. The live gate upgraded three installations generated by v0.3.5, rejected an old approval, and preserved an interrupted old transaction for recovery with the original CLI. Codex discovered the installed prepare and deliver skills and both references resolved to the expected OpenSpec and customer sources. [Unified Harness V1 verification](unified-harness-v1.md)
- **v0.4.1 follow-up.** Real Codex and OpenSpec passed mixed-project semantic acceptance and protected apply. The candidate resumed a durable v0.4.0 portable approval with CodeGraph and passed five local GitLab Runner scenarios. [Patch verification](unified-harness-v1.md#v041-functional-verification)
- **v0.3.0 follow-up.** The validation report separates the packaged Rigup lifecycle, native host discovery, CodeGraph EOF and daemon behavior, authenticated loopback MCP, and an approved T4 delivery through the installed Codex and OpenSpec harness. It lists the Claude authentication block and remaining external environments. [v0.3.0 validation report](https://github.com/ansonli-dev/rigup/blob/main/docs/compatibility/validation-0.3.0.md)
- **Claude Code with Rigup v0.3.x.** The public v0.3.2 npm package applied a deferred OpenSpec foundation on macOS arm64 with Claude Code 2.1.273 and on Windows 11 ARM64 with x64 Node.js 22.19.0 and Claude Code 2.1.322. Claude connected to Rigup MCP from the project root and a subdirectory on both systems. Both `claude:load` checks passed, and doctor exited 3 because project rules were pending. No model requests were made. A separate Windows 11 x64 reporter using v0.3.1 applied MCP-generated rules, then reproduced the retained OpenSpec reference error fixed in v0.3.2. [Claude smoke evidence](https://github.com/ansonli-dev/rigup/tree/main/docs/compatibility/evidence/2026-11-10-claude-v03-smoke)
- **Spec Kit research request size.** With Spec Kit 1.3.2 and the same Store Service fixture, filtering reduced the host analysis export from 267,057 to 21,159 bytes with legacy host settings and from 30,232 to 21,187 bytes with project rules enabled. OpenSpec 1.16.0 exported 20,066 bytes on the equivalent fixture. Spec Kit's constitution remained available, and the fixture made zero model requests. [Measurement and largest evidence paths](https://github.com/ansonli-dev/rigup/blob/main/docs/compatibility/evidence/2026-11-10-spec-kit/research-request-size.json)
- **Native Windows.** On Windows 11 ARM64 with PowerShell 7.6.9 and Node.js 24.22.1, the npm package installed OpenSpec 1.16.0 and ran a real Codex 0.166.0 preview, protected apply, and no-op update. CodeGraph 1.6.2 built and served an index. One Codex session initialized OpenWiki 0.7.3 with workspace write access and the local MCP server ready before the turn. Doctor observed both tool states and passed the project build and test commands. The regression suite passed 421 tests on Windows and 437 each on macOS and Linux ARM64, with platform-specific and opt-in cases skipped.
- **Claude Code on Windows x64 and WSL2.** The November 9 validation of Rigup v0.2.4 (`cf7cd0a`) used Claude Code 2.1.319 and Node.js 24.22.2 on Windows 11 x64 (build 26100, PowerShell 7.6.6) and Ubuntu 26.04 under WSL2. Default checks passed 424 of 463 tests on Windows and 438 of 463 on WSL2, with platform-specific and opt-in cases skipped. The live probe loaded an installed skill reference and invoked a read-only customer MCP tool on both platforms. On Windows, Claude also prepared and applied project rules with OpenSpec, preserved local edits, and followed the delivery skill in the tested prompt by waiting for an approved change. Delivery depends on the agent following that skill. Paths containing spaces or Chinese characters, an `E:` drive project, npm shims, and a junctioned `.rigup` were exercised. Pinned OpenWiki 0.7.3 and CodeGraph 1.6.2 answered MCP handshakes, and Claude queried CodeGraph. Full OpenWiki generation remains pending.
- **Windows x64 harness trial.** Three tasks ran once each with Claude alone and with Rigup plus each of OpenSpec, Superpowers, and Spec Kit. The baseline scored 4/4, 5/5, and 7/8. Its sole miss was a hidden test requiring a `refunded` status that the task did not specify. OpenSpec and Spec Kit scored 4/4, 5/5, and 8/8. Superpowers scored 4/4 and 4/5 on the first two tasks. Its third run ended at the step budget cap, so the 2/8 result is incomplete. The 12 displayed cells total $52.09 in CLI estimates. Relative cost varied by task and workflow, including $6.38 versus $0.30 (21.3×) for Superpowers on the first task. Planning artifacts were approved by the driver. A fresh-session OpenSpec delivery passed 5/5 for $1.47, versus $2.51 for resumed delivery in one pair of runs. The trial provides limited evidence about the effect of project rules or SDD in isolation.
