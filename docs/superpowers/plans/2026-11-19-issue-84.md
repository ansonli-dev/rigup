# OMP registry fallback implementation plan

> **For agentic workers** After controller approval, use the agreed Superpowers implementation workflow. Each task has a focused test cycle.

**Goal** Complete approved OMP Superpowers preparation when Windows denies symlinks and surface useful native failures.

**Architecture** OMP freezes an installation route in its approved action. Registry installation uses the existing protected native writer and verifies the Bun receipt and OMP bindings after dispatch. Both native hosts share a bounded stderr classifier.

**Tech stack** Node.js 22.19+/24, TypeScript, `node:test` via tsx, existing `jsonc-parser`.

**Spec** [Issue #84 design](../specs/2026-11-19-issue-84-design.md)

## Constraints

- Begin only after independent design and plan approval. Use the issue worktree at baseline `51406c2`. Reuse the installed dependencies. Launch local fixtures with disposable home, profile, temp and state paths and stub network requests. The controller owns the live Windows evidence.
- Keep `ompCommand(runtime, path, temp)` and the verified archive flow for link. Keep the current `ready` fast path and explicit approval, writer and project review gates.
- Keep `host-setup/index.ts` edits above `describeOutcome`. Issue #88 owns terminal rendering, associated i18n strings and renderer assertions. The controller owns the #85 Windows permission gate and audits the existing native smoke expectations.
- The approved digest comes from official metadata at planning time. The exact version and SHA-512 in the issue are regression inputs. Registry mode may update OMP/Bun state and must skip Rigup's `native-packages` store.

## Review focus

- Failure after a successful version probe exercises the final protected-dispatch recheck, including a capability flip and a redirected Bun receipt path.
- The fixture uses the real four-field registry tuple and trailing commas. Missing or ambiguous metadata, case of the wrong package, a digest or version mismatch, and skill shadowing each fail verification.
- An empty failure remains retryable. A rejected install left on disk stays blocked across invocations, including when all its skills look ready. Complete installations with no prior attempt keep ordinary discovery.
- An unusable Rigup archive store has no effect on registry mode. Successful retry does not run the registry command again.
- Stderr may contain credentials, paths, terminal controls, large prefixes and chunk boundaries. Only the bounded classifier's fixed messages reach either output mode.
