# Issue 89 · Provider Environment Import Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans after the controller's independent approval. Steps use checkbox syntax.

**目标**　CLI 提供方的调用环境输入须经明确选择才能随应用写入 .rigup/.env，实际导入密钥时默认给出提示。

**设计**　将提供方类别和密钥变量名保存在本次 SetupPlan 与 research continuation 中。由 runtime-inputs.ts 计算可写声明，使用现有私有文件 writer 及导入回执。

**技术栈**　TypeScript、Node 24、node:test、tsx、现有应用事务和双语字典。

**规范**　[Issue 89 设计](../specs/2026-11-19-issue-89-design.md)

## 共同约束

- 在隔离的 issue worktree 从 51406c2 开始。控制方批准设计和计划后开始下列测试和实现。使用现有锁定依赖。
- 所有 CLI 用例使用临时项目、HOME/USERPROFILE、缓存和状态。导入 test/helpers.ts 后显式设置合成密钥，前后隔离 RIGUP_PROVIDER、RIGUP_* model/URL/key-ref 及两个提供方变量。真实向导测试用 isTTY: true 和 read 传空行，限制空行次数以暴露意外提示，隔离 PATH/宿主检测。需要研究结果时注入 AnalysisBackend，禁止实际 provider 请求。
- 许可保存 provider、apiKeyEnv 和可选的显式 key-ref 布尔标记。保持 .env 现有 Git 和权限保护、非空内容优先、运行时读取、其他显式消费者和 JSON 字段。实现工序只在编号 1 完成后应用编号 2 的输出改动。

## 审查重点

- 同时提供完整 ambient defaults 或私有预设，仍不触发默认向导导入。任务 1 的默认与预设用例。
- 只在 apply/continue 进程出现选择器和 key，不能提升无许可的已保存运行。任务 1 的旧预览、旧 continuation 和恢复用例。
- RIGUP_PROVIDER 缺失时可使用审批中的提供方，当前 provider/key-ref 冲突时跳过写入。任务 1 的分进程用例。
- 无 Git 元数据、提示中键入密钥，随后才出现同名 ambient key。任务 1 的 prompt 用例覆盖 .gitignore 和存储边界。
- 写入受阻、已有值、重放与 verbose 不产生误报或重复。任务 2 的输出用例。
