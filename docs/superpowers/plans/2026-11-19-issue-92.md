# Issue 92 Implementation Plan

> **For agentic workers:** Follow the steps in order through a test-first run.

**目标** 让单行脱敏后的文件进入研究清单。

**实现** 在现有 read-policy 下补齐普通文本和 Markdown 内联的处理。保持仓库 reader 的证据行号及摘要契约。

**技术栈** TypeScript、Node.js test runner、tsx。

**Spec** [Issue 92 设计](../specs/2026-11-19-issue-92-design.md)

## 约束

同一文件的行数量和已保留的行对应原位置。读策略版本为 `9`。结构化配置、URL 过滤、文件级拒绝和 legacy 安装兼容沿用原入口。

## 审核重点

- 在普通代码和 Markdown 中匹配行后，前后证据可独立引用，摘要基于可见内容。
- 保存 CRLF 和末尾空行，Windows Wrapper 可读取，单行和跨行的 TypeScript 声明规则保持生效。
- 跨行键名与分隔符、块值、未闭合字面量、续行符、here-document 以及独立环境段继续拒读。Markdown 已支持的多行样例仍可读。
- 拒读文件名、私钥和二进制不会因单行过滤进入清单。旧安装清单的过滤规则仍适用。
