# Issue 94 Implementation Plan

> **For agentic workers:** Follow the steps in order through a test-first run.

**目标** 让证据读失败报告能定位引用。

**实现** 共用校验器提供诊断构造函数，MCP 补齐摘要时复用。

**技术栈** TypeScript、Node.js test runner、tsx。

**Spec** [Issue 94 设计](../specs/2026-11-19-issue-94-design.md)

## 约束

显示规范且有长度上限的仓库相对路径。固定原因可显示，原始异常内容留在读取边界。共享校验器保留结构位置，引用验收规则沿用既有逻辑。

## 审核重点

- 清单外路径与范围错误给出可区分的原因和路径。
- 读策略拒绝用固定文案。未知解析异常和操作系统绝对路径不会出现在诊断。
- 控制字符、未规范化路径和超长路径会省略，诊断仍能定位提交中的结构位置。
- MCP 失败后同一任务可改正引用并继续，且未错误计入接受状态。

## 实施

- [x] 在 `test/repository.test.ts` 通过实际 reader 引用清单外、无效范围和超出文件的路径。用变化中的文件触发策略拒读，模拟无法由文件系统稳定生成的未知读取错误，验证异常内容、超长路径和控制字符不进入诊断。在 `test/research-mcp.test.ts` 覆盖任务的失败和成功重试。
- [x] 运行 `node --import tsx --test --test-name-pattern='citation read failures|MCP citation errors' test/repository.test.ts test/research-mcp.test.ts`，确认缺失路径或原因的断言失败。
- [x] 在 `src/analyzer/backend.ts` 增加 `evidenceReadError(path: string, error: unknown, location?: string): ResearchValidationError`。从固定原因及已知系统错误代码选择文案。限定显示路径，保留调用者提供的结构位置。
- [x] 在 `src/research/mcp-workflow.ts` 捕获摘要补齐的 reader 失败并复用诊断。继续用原摘要比较接受有效输入。
- [x] 运行 `node --import tsx --test test/repository.test.ts test/backend.test.ts test/research-mcp.test.ts` 和 `npm run typecheck`。确认零失败后提交。
