# Rigup #86 原因本地化实施计划

> **评审门槛**　Controller 已独立审批规格、25 行矩阵及共享接口。按任务执行时使用 superpowers:subagent-driven-development 或 superpowers:executing-plans，并用复选框记录进度。

**目标**　让用户在 en 和 zh-CN 下读到完整的校验、准备和诊断原因，同时保留机器报告的原值和回退。

**架构**　在原因产生处构造代码和参数，沿现有运行链路携带，在终端按当前语言展开。错误、公开报告和已保存预览继续提供原字符串。doctor 的单条标签、原因及旧版 JSON 回退由独立格式化函数提供。

**技术栈**　TypeScript、现有 i18n 词表与 `AsyncLocalStorage`、Node `node:test` 和 tsx。

**规格**　[设计、基线和 25 项回归矩阵](../specs/2026-11-19-issue-86-design.md)。[CLI 中英术语表](../../guides/cli-terminology.md)。

## 全局约束

- 在分配的 issue-86 worktree 实施，基线 `51406c2`。复用固定 lockfile 安装与 Node 24。每组测试使用临时项目、HOME、缓存、状态和受控 PATH。外部工具用 fixture，npm 查询与 OMP 下载用注入或本地服务。
- 保留既有校验、安装读写、退出码、恢复分支、JSON 结构和字符串。保留命令、路径、环境变量名和标识符。结构化数据仅在进程中携带，保留原有签名与校验。未知原因按原文输出。
- #85 负责终端 `--agent` 拼写提示、`--sdd` 合法值提示、doctor 分组与帮助建议。配置文件中的 `sdd` 使用 #86 的原因及合法值提示。CLI 错误的 JSON `error` 使用旧英文。#87 负责结果标题和下一步，#88 负责原生进度和批准交互。

## 评审重点

- YAML 语法错误与 profile 校验能定位正确文件，CLI 与已批准选项的错误不被归到项目配置。任务 1。
- 系统中文的裸 `--continue nope` 进入 ID 校验，显式语言的同一调用进入选项校验。未知错误、`SyntaxError` 和非 Error 各有回退。任务 1。
- OpenSpec 第二条要求、Superpowers 组合原因、失败的原生步骤既出现在终端又进入既有报告路径。任务 2–4。
- CLI/MCP 读回的预览和中断恢复保留原有内容及签名。新预览的本地化信息沿内存副本到 verbose 详情。任务 4。
- doctor 的失败 JSON 回退不受分组或最后一行提示影响。检查源、环境项和未知诊断不泄露配置值，默认与 verbose 均可辨认条目。任务 5。

}

  readonly reason: ReasonInput;
  constructor(reason: ReasonInput);
}
