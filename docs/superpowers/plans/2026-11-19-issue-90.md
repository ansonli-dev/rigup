# 认领已有 Rigup 配置实施计划

> **给执行者**　独立评审批准本文和规格后，使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans` 逐项执行。

**目标**　从已初始化的克隆恢复 agent 选择及本机安装记录，保留已提交的字节。

**结构**　专用探测读取已注册的 MCP 目标。CLI 在已有审批入口之后、普通安装之前决定是否准备认领。认领计划沿用现有预览和安装 journal，应用入口校验零项目目标写入。

**技术栈**　TypeScript、Node 测试运行器、现有 JSONC/TOML/YAML 解析器及隔离测试里的真实 Git。

**规格**　[2026-11-19-issue-90-design.md](../specs/2026-11-19-issue-90-design.md)

## 约束

- 在指定的 Issue 90 工作树的 `51406c2` 基线上工作。使用现有锁文件依赖和 Node 支持范围，不添加依赖。
- 保留现有审批、路径和解析校验、恢复、显式配置及旧预览。认领只添加本机安装记录及项目外审批状态。
- 真实 Git 源、克隆、HOME、缓存、状态、测试 PATH 均使用隔离的临时路径。用会当场失败的假后端、npm 和运行检查注入保护认领测试，无需调用外部 provider、宿主、工具 registry 或修改真实 HOME。
- #85 接收现有 `nextCommand` 和 `Diagnostic` 字段。#86 接收相同的 agent、诊断及资产 ID。避免改变诊断的排序、布局、可视标签和全局状态词。

## 评审重点

- 一个名为 `rigup` 的用户服务和伪装的脚本参数都不能给出 agent。任务 1 覆盖这一点。
- 有启动器但绑定或入口损坏时保护现有文件，并给出具体路径。任务 1 和 2 覆盖这一点。
- 旧启动器的版本、CRLF、二进制、自定义技能复用与 Git 检出权限都影响基线。任务 2 覆盖这一点。
- 预览签发后权限、绑定、profile、Git 忽略的变化使批准失效。待提交 journal 仍以原 ID 恢复。任务 2 覆盖这一点。
- 克隆、空项目、PATH 和显式选择都应走各自的 CLI 入口。任务 3 覆盖这一点。
