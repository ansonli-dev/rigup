# #88 原生 Superpowers 输出实施计划

> 独立评审通过后执行。实现时使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，逐项验证。

**目标** 让首次向导和独立准备命令用同一套简洁的批准与结果文案。

**设计** 保留现有计划、原生执行与结构化报告。根据显示模式渲染批准范围和每宿主的最终状态。 [设计与基线证据](../specs/2026-11-19-issue-88-design.md)

**技术** TypeScript、Node `^22.19.0 || >=24.2.0`、`node:test`、现有 en 与 zh-CN 消息目录。

## 约束

- 从 `51406c25a348937ca0487aacde5bd4a3e691729c` 的指定 #88 工作树执行。使用既有依赖。夹具使用临时项目、HOME、状态目录和本地假宿主及下载响应。
- 保留双 TTY 和显式批准、Claude 精确目标复核、既有退出码及机器报告。默认每宿主每次批准最多三条换行分隔的文本行。详细文本走 `--verbose`。
- #84 提供实际 OMP 准备步骤和有界的安全 stderr。#87 处理原生段之外的结果、取消和重载。#85 管理整段脱敏快照和真实运行预期。

## 文件与接口

- `src/integrations/host-setup/index.ts` 的 `describeOutcome` 以下负责原生文本。保留 `nativeSetupInteraction(root, hosts, input, ui)` 的返回值及 `report`。为 `ui` 增加 `verbose: boolean`、`isTTY: boolean`，其中 `isTTY` 为原始交互具有输入与输出 TTY，`canPrompt` 还受策略限制。
- `src/cli.ts` 从 `runLocalizedCli` 将 `verbose` 传入私有 `runCliInternal`，在独立与首次向导两个 `nativeSetupInteraction` 调用点传 `{ verbose, isTTY: nativeTTY }`。复用 JSON 模式将 `io.isTTY` 置为 false 的路径。`CliIO` 无需增加公开字段。
- `src/i18n/en.ts`、`src/i18n/zh-CN.ts` 为 `native.*` 提供对应短文案。`test/host-setup-cli.test.ts`、`test/host-setup-blockers.test.ts` 使用现有隔离夹具断言原生段。

## 评审重点

1. 识别到既有来源时不会消耗批准。另一宿主需要写入时，已就绪宿主只有一条状态且无重开提醒。由任务 1、2 覆盖。
2. OMP 初始有下载阻塞仍可能复用，复用失败且有可执行备用方案时要保持原来的执行路径。由任务 1、2 覆盖。
3. 缓存了 Claude 目标但未声明 marketplace 时，两个命令同属首次批准。共享设置、用户状态与宿主缓存仍能辨认。由任务 1 覆盖。
4. 某一步确实写了文件不能成为另一失败步骤的清理依据。仅 marketplace 完成后取消，也不能呈现为安装成功。由任务 2 覆盖。
5. review 的 TTY 仍是人类界面。重定向和 JSON stdout 必须继续用原路由。由任务 3 覆盖。
