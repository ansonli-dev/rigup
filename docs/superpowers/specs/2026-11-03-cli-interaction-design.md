## 1. 已确定的方向

用户选择：**逐步向导＋可脚本化命令**，并明确要求**先问完、选完，再启动耗时流程**。首次运行可以从零完成设置，后续更新复用选择；向导和脚本调用共用 Analyzer → Generator → Installer 主线。setup 完成后退出，日常研发进入各 agent 的原生工具和已安装 skills。

考虑过三种形式：逐步向导适合有明确终点的安装任务，也容易保留非交互入口；全屏 TUI 更适合常驻会话，但会增加导航、终端兼容及状态管理成本；只展示推荐配置更短，但容易隐藏模型、SDD 和安装副作用的选择。采用逐步向导，已知值预填，高级项按需展开。

借鉴 OpenCode 的模型连接、模型选择、项目初始化分开呈现；本产品把这些动作串成一次 setup。补充借鉴 mattpocock/skills 的项目 setup：先探测已有约定，再按章节呈现推荐，只问尚未确定且会被所选能力使用的设置，最后预览写入。其项目 setup 是由 agent 执行的提示式 skill，与分发/安装 skills 的工具分开；本 CLI 在安装前收集必需约定，并将其接入独立运行的研发 skills，不要求用户装完再重复执行一套等价 setup。具体参考事实及来源见研究笔记；下面的界面、选项和规则均为本项目设计，不代表上游命令或能力。

适用本项目的补充规则：项目事实能回答的直接展示，已有用户约定保持原值，缺少的决策按条件提问；推荐值不是授权。每个 agent 的 skill 来源需明确，同一 skill 若已有插件和本地副本不再盲目复制；无法确认时报告待核实。

### 1.1 先集中决策，再连续执行

向导分为“准备与决策”和“执行”两段。前四步集中收集所选能力需要的输入，随后做快速预检并一次确认启动；长时间研究、生成和安装期间不再弹常规问题。初始界面说明将执行的阶段、交付结果和真正可能阻塞的条件。

默认推荐“按本次约定连续完成”：在已确认的项目范围、目标类型、具体操作和预算内，生成后自动保存预览、检查授权边界并安装，不默认要求用户等研究结束再回来确认。另可在启动前选择“生成后审阅再安装”，需要人工审核正文的团队使用此模式；--dry-run 则只到预览。

启动前集中确认：项目/研究范围、模型及凭据、目标 agents、SDD/工具、项目工作约定、版本与安装位置、可确定的命令与副作用、现存冲突、检查选择、预算/重试上限、可选能力缺失的处理方式、apply 前结束相关会话的安排，以及连续完成还是生成后审阅。host 正在用于研究且也是更新目标时，预先说明最终需退出该会话并从独立终端续跑，不能承诺这条路径无人操作。可由已有配置确定的展示摘要即可，不为了“前置”追加无关问题。

默认处理方式：可选研究信息未知则标未知，非必需正文可按声明策略省略；所选必需输入缺失在启动前阻止开始。执行中出现新增必需输入、未解决文件冲突、权限越界、预算耗尽或结果未知的外部动作时保存进度、集中报告并退出，不在 spinner 后弹问题无限等待用户。普通可恢复错误按已选上限重试，不能自行扩范围、换模型或降验收。

后生成的精确正文无法提前展示：连续模式授权的是明确限定的生成/安装范围，不是假称已审阅未知正文。研究完成仍必须生成真实 Preview，再由确定性代码核对它是否落在启动时的授权内；超出则停止，不能把前置确认当成任意写入许可。

## 2. 命令入口与首次启动

- `rigup`：TTY 中按项目状态进入设置或维护菜单；非 TTY 输出简短帮助和缺少子命令提示，退出 2，不自行初始化。
- `rigup init [path]`：首次设置；已有可信 manifest 时进入“已设置”分支，不重新认领已有资产。完全相同的配置可核实后报告无变更；需要生成或更新则转入同一 update 主线。
- `rigup update [path]`：沿用项目有效选择，重新分析、预览和更新。TTY 可在摘要中选择“调整设置”，脚本用 `--configure` 显式开启配置变更。
- `rigup doctor [path]`：默认只读诊断，不初始化、不修复；`--run-checks` 只运行明确选中的已有项目检查。
- 现有 `--backend native|host`、`--request`、`--response` 保留；native 表示独立模型后端，不表示目标 coding agent。

首次状态通过规范化目录、配置和 manifest 识别，不靠用户级“已看过欢迎页”标记。无 manifest 但已有配置/skills，仍走首次接入的保护规则；损坏 manifest 先报告诊断问题，不能当成干净安装。用户级默认 profile 只在已显式选择时参与，不为 onboarding 新建全局账户或配置中心。

```text
$ rigup

Rigup
项目  ~/work/payments
已有  Claude Code 配置、构建与测试入口
状态  尚未由 Rigup 管理

开始设置：集中选择 → 快速预检 → 确认启动 → 连续研究、生成与安装
Enter 开始    Ctrl+C 退出
```

已有安装时显示最近安装结果和当前待办，提供“更新配置 / 调整设置 / 检查接入 / 退出”。发现中断记录时优先提供“核对并继续上次操作”，详见第 6 节。菜单只路由命令，不引入常驻运行时。

## 3. 首次设置主线

### 第一步：确认项目与读取范围

先展示当前目录、检测到的仓库根/worktree 和是否有未提交修改。当前目录位于仓库子目录时，让用户明确选择当前目录还是仓库根；不静默向上扩大范围。路径确认前仅做定位所需的最小目录/Git 元数据观察，不遍历其他源码。

默认沿用用户指定路径或 cwd。monorepo 允许在确认根目录后限定研究模块；研究范围不改变安装根。无 Git 可以继续，不默认初始化。空项目只问可选的用途/计划技术栈，标记为用户意图，不写成已有实现。

显示只读发现结果：语言/构建 manifest、已有 agent/SDD 配置、检查入口、已有工单引用/文档目录/术语表/ADR、未知项。Git remote 仅作为工单平台推荐线索，不推定团队一定使用该平台跟踪需求，也不推定有远端权限。URL 在展示/导出前过滤凭据。仅在已授权读取范围及宿主可安全暴露的元数据内发现 skill 来源，标明本产品托管、本地用户内容、上游插件或未知；不为探测而安装/导入包、读取其他宿主凭据或扩大用户目录扫描范围。此时不调用模型、不执行项目脚本、不安装软件。发现失败不猜测不存在；未提交修改只提示会被保护，不要求清空工作区。

### 第二步：设置分析方式与模型

```text
如何分析并生成项目配置？

> 独立模型 API       本次由 CLI 直接研究和生成
  当前 coding agent 导出请求，由宿主处理后回传

独立模型配置
服务商  Anthropic（首版已实现的独立后端范围）
凭据    ANTHROPIC_API_KEY：已设置（不显示值）
模型    从有效配置读取；未配置时输入可用模型 ID

将发送：所选范围内经过读取策略过滤的代码和配置片段
预算：显示本次有效的读取/模型调用上限，可展开修改

> 保存模型设置并继续
  返回修改范围
  取消
```

服务商和模型只展示实际实现/可核实的选项；模型 ID 不猜测，不能因为 SDK 支持某种协议就展示尚未实现的服务商。凭据优先用明确的环境变量引用；缺少时可以在隐藏输入框输入一次性 API key，仅留进程内存，后续独立运行需再次提供或设置环境变量。不写入 config、manifest、缓存或命令历史；项目只保存引用名。首版不复制 OpenCode/其他宿主的登录文件，也不把宿主登录态当作本 CLI 的模型授权。

本页先收集设置，模型连接测试集中到启动前预检；用户可选立即测试，但不因此开始语义研究。测试使用不含客户代码的最小请求，说明可能计费；测试通过不代表已授权安装。原始代码读取/过滤边界沿用 Analyzer 设计，无法安全读取的区域列未知。全部设置收齐后才按最终范围与预算开始耗时研究。

错误就地给出原因和操作：凭据错误→重新输入；模型不可用→修改模型；网络失败→重试/切换宿主方式/取消。不能静默换模型、扩大预算或返回模拟分析。

宿主方式不要求 API key，不发独立模型请求。先完成其余确定性选项，再输出私有请求文件及可复制的宿主处理说明；按原生方式在 Claude Code、Codex、OpenCode 或 Oh My Pi 中处理，不发明通用 `/rigup` 命令。回传后继续主线，可能多次请求研究或生成正文；每次显示当前阶段、requestId 和准确续跑命令。宿主请求携带本次完整选择和缺失信息处理策略，不能在每轮重新询问同一组设置；宿主若已有受支持的自动调用/回传能力则沿同一授权连续处理。首版仅有文件手动往返时仍需真实回传，这项限制在启动前说明；希望离开终端持续完成时推荐独立 API 模式，不把手动往返宣传为无人值守。CLI 无法强制约束宿主自行额外读取文件的行为。

待回传通过统一 StepResult 从 backend/analyze/generate 返回，CLI 保存同一 run 的阶段/job、已接受候选、预算累计及授权关联，退出 3；未产生完整 SetupPlan 时不进入 preview/apply。每次回传先取得项目执行锁，校验请求后恢复未完成节点；已接受响应不重复消费，等待不重置预算或标为完成。宿主实际用量无法取得时明确 unknown，不虚构能控制宿主自身的总调用量。

### 第三步：选择要配置的 coding agent

```text
为哪些工具安装项目配置？（可多选）

[x] Claude Code   检测到已有配置；增量合并
[ ] Codex         未检测到；可生成项目资产
[x] OpenCode      检测到已有配置；增量合并
[ ] Oh My Pi      支持状态以锁定版本验证结果为准

Space 切换    Enter 继续    Esc 返回
```

“检测到”“已选择”“兼容已验证”“宿主已加载”分别显示，不能合并成一个绿色勾。检测到只作为推荐，不等于用户同意安装。首设至少选择一个有效安装目标：coding agent 或可独立工作的工具/hooks/自定义资产；完全无目标不能报告 setup 成功。

允许未在当前机器安装的宿主生成已支持的项目资产，结果标记为待宿主验证；未知格式/不支持版本不能强行写入。研究模型与目标宿主独立，例如可以使用独立模型为多个 agent 生成配置。

### 第四步：选择研发流程与可选能力

按组渐进展开，每组选项同时说明用途及副作用；没有选择的扩展不追问凭据：

- 研发流程：检测到的 SDD 优先推荐；可选 Superpowers / OpenSpec / Spec Kit / 不安装内置流程。每项目首版至多选择一种 SDD；已有多种时明确选择绑定对象，不自动卸载其余框架。不选 SDD 时保留工具/hooks/自定义 skills，不伪造原生研发进度。
- 知识与索引：OpenWiki、CodeGraph 分别可选。安装软件、初始化项目、为哪些 agent 接 MCP 分开说明，不因选一个就暗中开启所有远端功能。
- 工程反馈：展示已发现的 lint/test/environment/eval 入口及 cwd，让用户选择“接线”和“本次运行检查”。二者分开；每项执行说明环境、预期耗时和已知副作用。未选择运行项目检查时不执行这些命令。
- Git hooks / GitLab CI：按需启用；显示已有 hooks、CI 合并方式，无法安全串联时列人工待办。OpenWiki 的 CI 更新单独选择，说明凭据引用及写回位置。
- 客户扩展：本地 skill 目录及可选流程插入点、本地文本模板的 source/target/values、客户 MCP 的所选 agents/server id/命令或 URL/envRefs；只有选中的扩展才收集参数。范围及示例见 [Integrations 第 4 节](scaffold-modules/04-integrations.md#4-客户本地扩展)。命名冲突就地处理，不执行随附脚本；MCP 登记与启动/连接验证分开选择。部署绑定仅在客户已提供真实能力、目标、授权和恢复约定时可选；否则不生成 change-release。

#### 项目工作约定（同一步中的条件设置）

按 mattpocock/skills 的“章节推荐＋条件跳过”方式组织，不追加一张所有项目必填的表。先显示现状与来源，再只问所选流程实际需要且尚未确定的内容：

```text
项目工作约定

工单位置   发现 GitLab remote；尚无明确团队约定
推荐       GitLab 项目工单；也可选择本地文件或描述其他系统

文档位置   沿用已选 SDD 原生目录
项目上下文 docs/rigup/（建议，可修改）
术语与决策 已有 GLOSSARY.md、docs/adr/：直接引用
标签映射   未选择需要标签的能力：跳过

> 使用以上约定
  调整工单位置
  调整可配置的文档位置
  返回能力选择
```

- **工单与规格位置**：已有明确约定则保持，只有 remote 等线索时提供推荐但等待选择。无远端可用本地约定；未选择使用工单的流程时跳过。GitLab/GitHub/本地文件/其他系统可记录用途、项目标识或用户描述，但“记录约定”与“已实现可执行适配”分开；没有真实命令/MCP 适配时仅保存说明并列待办，不能承诺能创建工单。已有 SDD 规格是权威来源时继续复用，不再强制复制到工单。
- **标签词汇**：仅所选内置/自定义能力确实声明需要标签时出现。先沿用已有映射；缺失时展示该能力的默认角色供确认，用户可以映射到现有标签。未接入 triage 就不引入上游那五个标签，也不安装新状态机。选择标签不等于授权创建远端标签。
- **文档落点与领域知识**：分别显示 SDD 固定原生路径、可配置项目上下文路径、已有术语表/ADR 引用，避免一个“文档目录”参数把框架的固定布局改坏。已有布局不迁移；无既有约定时建议一个项目上下文入口，只有确有多个独立上下文且所选流程需要时再询问分区，不能仅凭 packages 数量自动创建多套术语表。术语表/ADR 尚不存在只记录按需维护的约定，不创建空文件，也不因此阻断 setup。
- **去重与入口接线**：展示所选 agent 实际可见的同名 skill 来源。来源明确且已满足依赖的复用；来源冲突让用户选择保留/绑定哪个，未声明选择时不安装重复副本、不卸载原插件。向多个 agent 安装时分别编辑必需的原生入口，引用同一份项目上下文，保留已有入口的非托管内容；不照搬上游“CLAUDE.md 存在就只写它”的单入口规则。

这些选择作为可选 `SetupOptions.projectConventions`（tracker、documentRoutes、labelMapping 及其必要引用）的一部分保存到现有 config，不增加第四份主协议或独立数据库。detected facts 只用于推荐，显式选择优先；所选能力的必需约定无值时 pending，可选信息缺失则跳过。生成的导航/说明是这些选择与权威来源的投影，不同时存一份可独立编辑的冲突配置；需修改约定时编辑 config 或 update --configure，用户修改生成说明仍受三方合并保护并提示回到权威来源。

初始化对工单系统的默认动作仅为记录约定及已授权的只读连通性验证。Git 初始化、增添/修改 remote、创建远端标签、迁移旧术语文件各自属于副作用，必须是实际受支持且被明确选择的具体操作，列入最终预览；客户授权缺失时保留待办，不能顺带执行。自定义 skill 仍只接收明确的本地目录，不因参考仓库支持 npx 安装就扩展为远端包发现/下载，也不自动执行上游 setup skill。

新装时可选扩展默认关闭，或由用户明确选择的 profile 预填；已有配置在 update 中保持不变。没有测试、eval、部署或组织负责人信息，不要求用户填一整套组织建设表；仅所选能力的必需输入成为当前待办。必需前置缺失则选择补齐、明确取消该能力或暂停；不能静默将必选项降为可选。

### 第五步：集中预检，一次确认启动

将前四步压成可回改的设置摘要，同时用固定集成映射完成生成前可确定的操作准备：锁定依赖版本、命令/写入范围和权限要求，核对已有目标所有权/明显冲突、必要凭据引用及检查环境。此处不能运行安装、索引或业务检查；允许已授权的只读连通性验证和最小模型连接测试。可选能力缺口集中展示，用户一次选择补齐或明确取消；必需前置缺失时不进入长流程。

```text
准备就绪
项目/范围  ~/work/payments；已选模块
模型/预算  使用本次设置的服务商、模型与调用上限
安装目标   Claude Code、OpenCode；项目级配置
文档范围   docs/rigup/；所选入口中的托管块
操作/检查  展示锁定版本、命令、初始化位置与已选检查
异常处理   有限重试；未知信息记录；冲突/越界保存后停止

完成方式
> 按以上范围连续完成（推荐）
  生成后先审阅，再安装
```

连续模式的确认生成本次私有授权记录，绑定项目根、有效选项/策略版本、预算、受管目标/允许新增的文档目录、预检观察到的目标摘要、明确安装/初始化/移除/检查操作及版本。新增文档只允许位于已选目录且不接管现有无所有权文件；机器配置和命令固定，不能由模型添加新副作用。可选能力缺口如何处理也绑定到记录。授权只是本次执行的缓存数据，不增加第四份主领域对象，不记录秘密，不成为长期覆盖许可。

开始后进入执行阶段，仅显示可持续观察的进度与日志，不再询问偏好。先完成本地可做的规划，宿主模式在实际需要模型的节点按已说明的往返方式处理。

预览包含绝对目标根、每个托管文件/块、依赖版本与安装范围、外部操作、初始化写入位置、选中的项目检查和明确移除项。凭据不进入 diff，未知命令或未声明写入范围的操作不能执行。审阅模式默认焦点为查看差异，不能连续按 Enter 就完成未审阅安装；仍允许用户直接选择确认，无需强制逐文件翻页。连续模式不出现此菜单，也不等待 pager 输入，完整差异和日志保存为可查看报告。

审阅模式的此处确认绑定当前 preview；连续模式则将真实 preview 与启动时的授权逐项比较，检查通过后绑定该 previewId 并调用 apply，不再次询问。两种模式执行中均不逐文件重复确认；客户平台必需授权仍保留。新增/变更目标、版本、命令、副作用或预算超出授权时停止并报告，待下一次集中处理并重新预览。选 `--dry-run` 时到预览即结束，不显示执行项；模型研究可能仍有网络和计费，只保证不安装/写客户项目。

首版有未解决冲突时不开始 apply；连续模式保存并报告全部已发现冲突后退出 1，不自动弹出问题等待。审阅模式或下一次续跑的准备阶段进入冲突处理，选择修改选项、手工合并后重新预览，或退出。人工接管已有文件、恢复用户删除的资产、覆盖用户改动、移除修改过的托管项都需要逐项明确选择，随后重新预览；不提供一次性“覆盖全部”。只读差异查看不能顺便更新 baseline。

逐项裁决作为 Installer 私有预览输入 `PreviewResolution { target, selector?, observedDigest, action }`，action 限于 adopt/restore/replace/remove；不写入长期授权配置。内部 `preview(plan, resolutions?)` 校验目标/选择器和当前完整摘要，产出新的 previewId；apply 只执行该预览保存的具体结果。目标变化后旧裁决失效，必须重新裁决。接管只覆盖明确选择的托管范围，保存的 baseline 仍是本次生成的 N，不复制原文件/合并后的用户内容；restore/replace 同样以 N 为新基线，remove 成功后注销对应 ownership，未解决项不更新清单。人工修改文件再预览时也重新比较实际状态。

外部初始化还展示已有文件的保护方式/工具状态前置，不能把 declaredWrites 当作覆盖许可；具体准入见 Installer 第 3.1 节。更新预览逐项交代旧托管资产的保留/更新/退役/待处理，漏项或已知失效且仍可加载的规则阻止 apply。最终合并/保留内容按 Installer 第 2 节核验必需入口、绑定及引用；没有文本冲突也可能有接线阻塞，报告具体位置并保留用户内容。项目检查失败只影响对应结果和退出码，不抹掉已成功接线的 manifest/baseline。

## 4. 更新交互

普通 `rigup update` 读取有效项目选择，显示“保持的设置 / 项目变化 / 需重载的宿主”，先集中预检并确认本次完成方式，再进入研究/候选与预览，不重问首次设置各页。已有项目工作约定直接复用；新增能力仅询问它新增的必需输入。更改工单系统或文档路由只生成具体变更/待办，不自动迁移既有工单、文件或研究进度。交互用户可选择调整设置，`--configure` 显式进入设置页；服务商、读取范围或预算变化要更新数据流说明。

配置优先级仍为显式参数 > 项目配置 > 明确选择的 profile。模型、SDD、工具版本不因 update 自动升级。停用能力在预览中形成明确移除项，保留修改过的用户资产；不卸载共享工具。无变更、候选缓存完整且版本不变时复用生成结果，仍检查完整目标的删改。

实际 apply 更新配置/skills 前要求结束会加载待改资产的 agent 会话，以用户确认/已有自动化约束为准，不检测研发 lease。host 可以先完成研究及最后响应，处理说明要求随后退出相关会话，再从独立终端运行准确续跑命令；这是启动前已说明的技术交接，不新增业务问答。自动回传若仍在待改宿主内，则保存已接受候选、列出停会话待办并退出 3，不等待输入或热更新。独立终端续跑重新核对该执行条件及预览，沿用仍有效的本次范围；取消/失败后的新一轮仍遵守第 6 节。更新不读取或迁移 SDD 在途任务。

## 5. 非交互与参数语义

首版只保留 --configure、--dry-run、--json 等表达具体目的的选项；不另设“禁止提问”或“统一答是”的开关。脚本化的价值是复用已确认设置并完成工作，交互方式由运行环境及调用意图自动决定；读取预算、范围和能力通过同一 SetupOptions 的项目配置或已实现的覆盖参数提供，不另建 wizard 配置协议。完成方式及有界异常策略作为可选 executionPolicy（continuous/review、可选缺口策略和重试上限）保存到现有选项；保存的偏好不等于下一次执行已获授权。无终端或 --json 调用中的 --configure 只应用明确提供的配置变更，不弹表单。

- 先按显式参数、项目配置、已选 profile 解析有效设置，再做只读探测，补充可确定的事实和无副作用的默认值；例如已知项目根、已有命令/文档位置，不要求重复填写。能力选择、数据发送范围和授权不能靠猜测补齐。缺少可选信息时按预定策略省略，不以字段不全为由退出。
- 人工 TTY 调用在启动前只补问仍未确定且必需的事项。无 TTY 或 --json 调用自动走可脚本化路径，不读取 stdin；设置完整时直接继续。只有凭据、明确目标、必要授权等确实无法取得或推断的必需输入仍缺失时，才在预检集中报告字段、已尝试的来源、提供方式与续跑命令并退出 3；字段格式错误退出 2。不能把“缺了就退出”作为主要自动化能力。
- 直接调用 init/update 表达按明确参数和已确认项目配置完成本次设置/更新的意图。脚本不需要额外的同意开关：预检先核实目标、数据范围、预算和具体操作，生成后再将真实 preview 与该范围匹配，匹配才执行；显式调用不授权新能力、全局安装、额外外部写入、冲突覆盖或取消客户 gate。
- 自动化运行沿用同一配置与执行模式：continuous 时预检通过就连续完成；--dry-run 仅生成预览。若项目明确要求人工审阅而当前无法输入，启动前报告该 gate，不能等生成后才暴露，也不能绕过。TTY 的启动确认只用于集中完成首次选择/变更选择，配置已明确时不重复询问相同授权。
- `--json` 输出单一最终 JSON 对象到 stdout，禁用交互；进度到 stderr，禁用 ANSI/光标控制。最终对象含 phase、installStatus、检查结果、pending、conflicts、requiredInput、nextCommand 及脱敏报告位置。stdout 不能夹欢迎语。
- `--dry-run` 明确选择只预览，绝不执行安装、初始化、项目检查或修改项目；允许已授权的模型调用及私有缓存写入。doctor 的默认只读检查不调用模型。

```sh
# 人工首次设置
rigup init .

# 通过项目已有有效配置，在自动化中生成与安装
rigup update . --json

# 仅研究并预览；凭据、范围与预算须已配置
rigup update . --dry-run --json

# 宿主往返示意；实际路径由上一轮输出
rigup init . --backend host --request /absolute/private/request.json
rigup init . --backend host --response /absolute/private/response.json
```

`--request <path>` 是本轮宿主请求的导出目标，`--response <path>` 是响应输入；二者互斥。请求默认写在本项目的用户私有缓存目录；显式导出路径也必须位于该私有目录内，拒绝项目树、符号链接逃逸和覆盖未知文件。响应可从显式本地路径读取，但必须校验 requestId、阶段、输入指纹和格式。每个请求还保存 requestDigest，绑定 runId、规范化项目根、任务/产物 ID、研究指纹、旧托管库存摘要、有效选项（agents/SDD/范围/预算、客户模板源摘要/参数、MCP 非秘密配置等）、读取策略及 prompt/模板/文档标准/集成版本；响应须回传同一摘要，并与当前有效上下文重新比较。任何绑定项变化后旧请求/响应失效，重新导出请求，不能只因源码未变而接收旧结果。响应不是执行命令，也不是安装授权；继续执行仍要生成真实预览并检查启动时的有界授权和停会话条件，匹配则连续完成，不匹配则报告停止。多轮 host 往返通过同一项目缓存定位未完成请求，不增加独立服务。

退出码：0 表示请求的安装/预览/诊断动作完成；1 表示安装/诊断执行失败或未解决冲突；2 输入错误；3 必需外部输入、初始化/加载待办或待宿主续跑。选中的项目检查失败优先退出 1，但 installStatus 仍可为 complete。未选测试/eval 的 informational unknown 不单独强制退出 3；所选必需能力的缺失才算 pending。多状态同时出现时按 2（尚未执行的输入错误）→ 1 → 3 → 0 判定，JSON 保留每项事实，不能只靠进程退出码判断安装是否成功。

## 6. 中断、冲突与恢复

Ctrl+C 先停止调度新操作，标记当前动作为 cancelling，并请求停止受管的本地子进程/进程组；确认可能写项目的本地进程已退出且本地写入结束后才释放锁，进程退出 130。等待终止有上限；无法确认时保留进程身份、操作范围和阻塞记录，不将该项目显示为可继续安装；重进先核实旧进程与实际结果，不能仅凭 CLI 已退出自动夺锁或重新初始化。锁及未决操作记录位于用户应用状态目录，和可丢弃生成缓存分开；清空普通缓存不消除阻塞。对于已发出的远端动作保存 unknown 结果，按查询/人工对账处理，不承诺 Ctrl+C 能取消远端副作用。取消发生在生成前不写项目配置，用户选择只在私有草稿缓存中；安装确认后才落项目 config。安装中已完成的文件及初始化效果保留，显示准确续跑命令和备份位置，不提供全局自动回滚。

再次运行相同命令时，先对照真实目录、当前输入、选项和版本：匹配→恢复候选；不同→说明失效原因并重建。**恢复一律核对实际动作，重新形成预览。** 同一次未结束的技术性宿主往返可继续使用仍匹配的本次有界授权；Ctrl+C、执行失败/阻塞后用户发起的新一轮续跑，则在恢复准备阶段一次确认当前范围和异常处理，再开始耗时步骤，不沿用旧的人工 preview 确认放行新副作用。同项目锁冲突仅报告正在运行的信息，不自动夺锁。

执行锁覆盖首次研究、host 导出和生成，不只覆盖 apply；第二个活动进程不能先改当前请求/候选。host 待回传时保存 run 后释放锁，回传重新取得；候选按 runId 隔离。同次待回传或停会话交接期间没有本地写进程时不持锁空等，但未决外部效果仍按阻塞记录核对。

结果不明的外部操作先查询；不可查询则列人工待办，不给“立即重试”按钮。Installer 第 4 节要求副作用发出前持久保存未决操作，强杀/崩溃后沿用同一对账规则，不依赖 Ctrl+C 处理器。缓存丢失时重新扫描，不认定安装未发生，不覆盖没有可信基线的文件。未完成操作涉及哪些依赖项要显示，允许用户明确取消可选能力后重规划，其余成功配置不以失败为由删除。

## 7. 终端行为与展示约定

单列内联向导，每次提交保留简短已选摘要；方向键选择、Space 多选、Enter 提交、Esc 返回，Ctrl+C 退出。Esc 返回使依赖该选择的下游候选失效，并显示将重新生成的范围。秘密输入不回显、不保留在屏幕历史。

纯文本模式支持编号选择和逗号分隔多选，不依赖颜色表达状态；窄终端路径可折叠但差异查看仍能展开完整路径。NO_COLOR/TERM=dumb 禁用装饰及光标重绘，需要输入的准备/审阅阶段遇到 EOF 按取消处理，不能套用默认确认；连续执行阶段不读取 stdin，启动后 stdin 关闭不影响既定任务。分页只用于准备/审阅阶段 TTY 的差异/命令清单，非交互不启动 pager；所有外部输出遵守脱敏边界。

交互语言首版统一中文、保留命令及工具原名；文案可集中维护，但首版不增加语言设置页。UI 实现采用薄的 CliIO/prompt 适配层，运行逻辑不读取终端按键；不在此锁定尚未核验的终端 UI 库。

### 7.1 全程进度与预期管理

**准备阶段也有指引。** 每个问题显示“当前章节 / 余下章节 / 为什么需要这个选择 / 推荐来源”，例如“工具与流程：之后还需项目约定、预检和启动确认”。条件章节尚未确定时不显示虚假的总题数；每组选择完折叠成简短摘要。预检逐项反馈模型连接、凭据引用、版本、目标冲突等状态，用户无需猜测是在思考还是等待网络。

**执行页保持固定信息层次。** 顶部是项目、当前阶段编号与名称；中间是阶段清单和当前子任务；底部是已用时间、剩余耗时区间、下一步、是否需要用户操作、最近反馈及日志位置。阶段结束给一句具体成果（如“8 份候选已保存，开始检查现有配置差异”），再自动进入下一阶段。完成提示音/桌面通知不作为首版必需功能，不为持续提示引入后台服务。

完整安装的六个执行阶段是研究项目、生成候选、预览检查、安装与初始化、验证、报告。这是执行阶段，不是前面的七步向导；配置阶段明确区分，避免两个编号系统混用。--dry-run 在预览报告结束，阶段列表不包含安装/项目检查；不涉及的能力不占空阶段。页面始终展示本次实际启用的阶段与后续动作。

**进度分为准确计数和整体估算。**

- 准确计数来自完成事件：生成 4/8 份、配置写入 3/5 项、检查完成 2/4 项。只有保存候选并校验通过才算生成完成；重试、发出模型请求或 token 到达不算完成。无固定分母的研究/索引显示阶段、已处理量及当前操作，不编造局部百分比。
- 整体百分比仅在有可比阶段耗时依据时显示并标为“预计整体进度”；没有依据时显示阶段、准确子任务计数和“整体耗时进度待估算”。首版不维护一套固定初始权重，也不将阶段数比例当作时间比例。
- 无计数分母的当前阶段不按时钟自行推进；持续更新活动和已用时间。任务清单确定后冻结本轮计数分母，缓存复用项单独标“已复用”，计入对应完成量。必要的任务重规划须显示“发现新增工作，已重新估算”，更新 planVersion 和分母；已有整体估计失去依据时撤回，不能隐蔽倒退百分比。
- 失败、重试等待、人工等待不能显示 100%；完整安装只有本次必需步骤和报告成功完成才到 100%。已声明跳过的可选项显式计为 skipped，不伪装为 passed；实际待办分列。--dry-run 的 100% 只表示预览已完成，明确“尚未安装”。

**预计耗时给区间、依据和变化原因。** 先实现阶段、计数、已用时间、等待和下一步；历史统计不阻塞主线。只有本次同类已完成任务或已有可比计时足以支撑时才显示粗区间及样本数，样本不足就显示待估算。比较应考虑阶段/操作类型、模型版本、规模和缓存命中，不混用明显不可比样本；算法与最低样本数由实现选择并验证，不把固定阈值当作产品需求。若保存统计，使用已有私有缓存，仅含计时/规模元数据，不上传遥测或存正文/凭据。

剩余区间按各串行剩余任务的可比样本区间求和；当前进行任务需考虑已用时间，超过样本上限时撤回该任务原预测，显示“超出原估计，重新估算”，不能得到负数或持续显示“还剩 0 秒”。重试退避计入预计剩余；未知的远端等待、模型首响、索引器/测试无可比样本时分别标“该阶段待估算”。只要还有无上界估计的必需阶段，就不显示貌似完整的总剩余区间，改为“可估算部分约 X–Y 分钟，另有 Z 个阶段待估算”。

无可比证据时显示“已用 40 秒；预计剩余时间正在估算”，同时给阶段数、完成计数和后续列表。运行中获得足够样本就自动更新，不能在首次启动时凭空承诺“5 分钟完成”。预计值按阶段切换、完成事件或每 10 秒更新，明显延长时说明原因，例如“网络重试，预计增加约 1–2 分钟”。宿主手动往返/审阅等待从主动执行 ETA 中排除，明确“等待宿主响应/等待你审阅”，同时保留总墙钟时间；停止倒计时，不能显示仍在后台生成。

**长任务的存活反馈。** TTY 每 10 秒刷新已用时间和存活状态，即使子进程无输出也显示“进程仍在运行，上次有效进展距今 X 秒”；非 TTY 在阶段变更/任务完成输出一行，静默阶段每 30 秒追加简短状态行。心跳仅证明编排器/进程存活，不能当成工作进展。连续 60 秒无有效进展，显示当前等待对象（模型首响、网络、索引、测试等）、当前操作的已用时间与已配置超时/重试上限；达到实际上限执行既定策略，不每 60 秒询问用户。

工具提供 bytes/items/测试用例等原生进度时展示，并标明其语义；不支持时使用计时、进程状态和已知日志。不能把解析失败的上游输出当成已完成。可恢复重试显示“第 2/3 次、原因、下次重试时间”，不明结果显示“正在查询实际结果”；真正停止时明确哪些结果保留、剩余哪些工作、具体下一步/续跑命令。提示与更新均不读取 stdin，不打断连续执行。

**事件与输出共用事实。** 内部轻量 `ProgressEvent` 包含 runId、planVersion、phase/task、status、completed/total（可空）、elapsed、最近有效进展时间、ETA 区间与依据（可空）、nextAction 和 requiresUserAction；使用可注入时钟计时，脱敏渲染到 TTY/纯文本和私有日志。只新增 UI 事件适配，不建立任务调度器或新进度数据库。--json 仍只在 stdout 输出最终对象；stderr 记录无 ANSI 的进度，最终报告保留阶段用时、真实结果和下一步，估算值不能影响退出码或验收结论。

## 8. 对现有实施计划的补充落点

本节已在本轮文档收口中落实到现有任务，不另建并行实施主线；“已落实”指计划条目齐全，不表示测试已经通过：

- Task 1：无参路由、TTY/非 TTY、prompt/CliIO、轻量 ProgressEvent 和共享计时/渲染适配、输入优先级与秘密输入；业务未接通时仍返回未实现。
- Tasks 2–5：只读检测摘要、模型连接测试、能力筛选、预算、宿主多轮请求和真实生成进度（真实完成计数、无进展心跳、剩余耗时区间与依据）；发现已有项目约定/skill 来源，按实际消费者收集 tracker/documentRoutes/labelMapping 并接入生成资产。
- Tasks 6–7：设置草稿、启动前集中预检/有界授权、连续模式自动绑定实际预览与无中途问答、可选审阅模式、具体差异与副作用、授权绑定、逐项摘要绑定的冲突裁决及 baseline/ownership 更新、旧库存逐项去向、外部写入保护、冲突阻止 apply、安装结果/恢复与退出码；执行锁也覆盖生成，普通缓存丢失不解除未决写进程阻塞。
- Task 8：doctor 与检查选择，分别展示 configured/available/initialized/reload-required、项目检查/eval。
- Task 9：TTY 输入脚本覆盖完整首次向导、已有项目更新、条件问题跳过/只问新增必需项、单/多上下文、已有 skills 去重、无术语文件不建空文件、工单说明不冒充适配、remote/标签默认不写、返回修改、Ctrl+C、EOF、宿主多轮、选项/策略变化拒绝旧响应、缺凭据、无 Git/空仓库；自动化覆盖已有设置/安全默认值/可选缺口的解析后正常执行、必需输入无法取得才报告、--json 单对象、无 ANSI、缺值不挂起、直接调用不扩大配置范围、dry-run 无安装副作用。实际宿主发现及生成验收仍以原计划真实证据为准。

最低行为验收：准备、执行、等待、重试、失败和完成均能说明当前位置、后续工作及用户是否需操作；进度计数、整体估算与 ETA 有明确依据；无输出长任务持续反馈，超时不挂起问答；首次用户不手写配置即可走完一次受支持的设置；已知必需输入缺失时模型研究/安装次数为零；确认启动后移除 stdin 仍可在既定范围连续完成；执行期间未知信息/可选失败按已选策略处理，异常阻塞只输出汇总与续跑信息、不调用 prompt；审阅模式才在生成后等待确认；更新不重复问答；未授权不写项目；无 TTY 不挂起；冲突不覆盖；不明外部动作不盲重试；接入状态不掩盖项目检查失败；每次退出都给出当前结果和可执行的下一步。
