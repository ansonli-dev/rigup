# Issue 94 · 证据错误包含路径和可处理原因

[Issue #94](https://github.com/ansonli-dev/rigup/issues/94) · [核查基线 `ee6648c`](https://github.com/ansonli-dev/rigup/commit/ee6648c7147f642f88d3ff9381d58a1b9765da85)

## 已核实

合成项目中引用不存在的源码和越界行号。共用校验保留 `research.[field][0]` 等结构位置，两个失败都变成了同一句通用报错。MCP 会先尝试补齐引用摘要，直接返回 reader 原因，缺少引用路径。文件系统和解析器的原始异常可能包含本机绝对路径或源文本。[共用校验](../../../src/analyzer/backend.ts) · [MCP 证据预处理](../../../src/research/mcp-workflow.ts)

## 设计

传递所有底层错误会扩大本机信息暴露。只更新共用校验会遗漏 MCP 的第一处读取。选择在两个入口复用同一安全诊断。

- 对可安全显示的引用输出 JSON 引用的仓库相对路径和固定原因。可显示的路径必须规范、有限长且无控制字符。保留共用校验器的结构位置。CLI provider 的诊断与自动修复请求只使用结构位置和固定原因。
- 区分清单外、行范围无效或超出文件、策略拒读等固定原因。文件系统错误只根据已知代码选固定文案。其他失败显示通用原因。
- 保持拒读、作用域校验、摘要验证和重试语义。在未接受失败提交的情况下，可以用同一 MCP job 重新提交有效引用。
- 按 issue 的优先级实现逐条诊断。宿主从错误中定位需替换的引用。
