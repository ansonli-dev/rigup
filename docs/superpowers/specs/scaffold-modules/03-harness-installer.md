# Harness Installer：安装与更新

所属：[总架构](../2026-11-02-smart-harness-design.md)。

## 1. 接口与职责

```typescript
preview(plan): Promise<Preview>
apply(previewId): Promise<InstallReport>
```

preview 读取实际目标、安装清单和基线，生成可审阅的最终差异；只写私有缓存。apply 校验该预览仍有效，再执行。模型不会在 apply 时补写内容。

规划与执行是同一模块的两个操作，合并规则和实际文件状态集中在此维护。

## 2. 预览与合并

读取 .harness/manifest.json 和 baseline。对每个托管文件/配置块比较 B（原生成）、L（当前）和 N（新候选）：

- 不存在且无 B 的目标创建；有 B 而 L 消失视为用户删除，未经明确恢复不重建。L=N 不写；L=B 更新；N=B 保留用户修改。
- 三者不同只合并不相交变更，否则保留 L 并报告冲突。
- B 不可信或缺失且 L 已存在，不自动认领覆盖。

结构配置由集成实现合并具体键或标记块，保留无关字段与注释。无法安全处理时提供人工片段，不重写整份配置。

移除仅处理明确列出的托管项。未修改可删除/解绑，用户改过则冲突保留；不自动卸载共享软件，不把遗漏当作删除指令。

## 3. 执行顺序

1. 取得目标目录对应的安装锁，复核源码/选项、目标文件及工具版本。
2. 保存必要备份，执行明确选择的目录/Git 初始化及软件安装任务。
3. 写入所选配置、skills 和说明。
4. 初始化 OpenWiki/CodeGraph 等所选工具，调用声明的验证。
5. 保存新生成基线，再原子替换 manifest，输出成功、待办与失败项，退出。

新基线写到独立的 baseline/<installId>/，manifest 切换前保留旧基线，避免清单写入失败时旧 B 已被覆盖。这是文件比较所需的备份，不是运行中的多版本交付包。

使用普通顺序任务列表，不需要安装 DAG、通用 ActionDriver 总线或多阶段 bundle 激活。前置任务失败就停止相关后续动作，不执行依赖它的配置。

版本、路径和副作用范围都在预览中列明。安装命令不得暗中改未声明位置；上游工具无法限定或说明写入范围时，使用明确模板/人工方式。

## 4. 失败与重试

私有进度记录保存任务 pending/done、文件前后摘要、备份位置及外部结果。重跑先检查实际状态；工具已安装或索引已建立则验证后复用。

超时的远端操作先查询实际结果，不能盲目再创建。无法可靠判断时停止并报告，不保证跨系统精确一次。

多文件不是整体事务。失败可能留下部分成功配置；提供备份、Git diff 和下一步，重跑重新预览。不能自动 reset 用户工作区或强行回滚用户新修改。

manifest 失败时不把此前效果当作未发生。缓存仍在则对账后继续；缓存也丢失则重新扫描，有可信基线才合并，否则冲突保留。接受人工处理边界，不为它引入事务平台。

## 5. 锁与更新边界

缓存/锁以规范化目标目录区分，不依赖是否已有 Git，避免 git.init 时迁移状态。锁只防止同一目标目录的重复安装；跨 worktree、跨项目用户级配置和多机器并发不在首版保证内。

update 前结束相关 agent 会话，更新后重载配置。Installer 不检测/管理研发 lease、不读取审批、不迁移在途任务，不承诺旧会话继续使用旧工具版本。全局工具升级需显式选择，影响不明则保留并提示。

## 6. 报告与测试

配置写入、工具初始化、宿主加载和项目检查分别报告。需重启、无源码、缺凭据/环境是具体待办；测试失败不触发业务修复。

测试三方合并、注释保留、显式删除、外部编辑前置检查、重复安装、任务中断、manifest 写失败和远端超时。另验 CLI 不可用时已安装资产仍能运行。
