# Harness Generator：配置与内容生成

所属：[总架构](../2026-11-02-smart-harness-design.md)；参考：[OpenWiki 源码研究](../../../research/2026-11-02-openwiki-analysis-generation.md)。

## 1. 职责与接口

```typescript
generate(profile, options): Promise<SetupPlan>
```

生成器内部完成选项检查、工具映射、语义产物规划和内容渲染。输入固定后产生具体文件/修改意图和安装任务，不写最终目标，不运行安装命令。

不再向 CLI 暴露 Resolution、GenerationPlan、AcceptedArtifactSet 等多层公共协议。

## 2. 选择集成

显式参数优先于项目配置，其次是用户选择的默认 profile。使用简单注册表找到所选 agent、SDD、工具和客户集成。

读取对应版本的模板/能力映射，检查必需入口及依赖。不做通用依赖求解器，发现冲突或不支持项就报告。普通 update 不顺便升级所有工具。

没有 SDD 时可只配置工具、hooks 和自定义 skills；没有真实部署能力则不生成可执行发布入口。

## 3. 动态规划与生成

1. 根据所选能力列出必需资产；固定机器配置及强制流程步骤由集成实现决定。
2. 模型根据 ProjectProfile 规划规范、模块说明和流程 references，列 logicalId、目的、研究起点及相关产物。
3. 校验范围、重复项和必需项，形成普通串行清单；导航相互引用允许成环。
4. 每项使用局部上下文继续核实源码并生成候选，汇总/导航内容最后生成。
5. 校验格式、来源及能力引用，保存候选后才标记该项完成。
6. 组装候选与固定模板，生成 SetupPlan，交给 Installer。

不同项目可以有不同内容和文档粒度。动态生成不是简单变量替换，但也不允许模型任意增加公开 skill、改审批政策或发明上游命令。

## 4. 小型生成缓存

私有缓存只需保存输入指纹、产物清单、每项 pending/done 状态、候选路径/摘要与错误。不是独立任务平台。

先保存候选，再更新 done；重启时检查候选仍存在且匹配摘要。中断于两者之间可重新生成该项，接受少量重复工作，避免复杂的精确一次协议。

输入未变时复用完成项；输入或选择变化时保守重建生成清单。首版不承诺完整 Claims ledger、逐事实依赖图或运行中任意任务的精确失效。

限制每项重试和总预算。必需项失败不能用占位文本完成计划；可选项按声明的缺失策略报告。

## 5. 输出与确定性部分

SetupPlan 列出目标文件/配置块、候选内容、安装/初始化任务、明确移除项、来源和警告。

固定命令、机器字段和 gate 不交给模型自由渲染；生成脚本不依赖 installer 包。模板组装和路径映射在相同输入下稳定，模型正文不要求每次重跑相同。

入口只放通用命令与知识索引，模块规范和流程 references 按需引用，并保留权威来源/维护者。研发模板在现有 SDD/工单中承载目标、范围、验收、允许操作、预算/停止条件和接手人；按任务风险控制文档厚度，不另建协议引擎。风险政策来自客户，不按改动行数或模型自评自动放行。

只有显式停用或明确提出的托管文档退役才进入移除清单；省略、生成失败和输入未知不等于删除授权。

## 6. 测试

验证单服务/monorepo 产生不同的合理清单、必需项未完成会阻止成功、重复 id/路径被拒、候选损坏需重做、输入变化不沿用旧结果、模板保留原生约束，以及源码和客户最终配置没有被生成过程修改。
