# Rigup Generator：配置与内容生成

所属：[总架构](../2026-11-02-rigup-design.md)；参考：[OpenWiki 源码研究](../../../research/2026-11-02-openwiki-analysis-generation.md)。

## 1. 职责与接口

```typescript
generate(profile, options, backend, previousAssets = []): Promise<StepResult<SetupPlan>>
```

按[总设计 1.1](../2026-11-02-rigup-design.md#11-整个脚手架的确定性与-agent-边界)区分两种生成：代码/模板渲染机器配置、脚本、技能固定流程并绑定参数；agent 仅规划受限语义产物、理解复用来源并生成必要项目正文。固定字段/流程不由模型重写；无语义任务或有效缓存足够时不调用 backend。

生成器内部完成选项检查、工具映射、语义产物规划和内容渲染。输入固定后产生具体文件/修改意图和安装任务，不写最终目标，不运行安装命令。

不再向 CLI 暴露 Resolution、GenerationPlan、AcceptedArtifactSet 等多层公共协议。

previousAssets 由编排层从可信 manifest 读取，只包含旧托管项身份、目标/选择器和基线引用；旧正文可作为更新上下文，不充当独立规范证据。backend 返回 pending-host 时本模块保存当前 job 和已接受候选并向上返回同一暂停结果；只有完整且可验收的计划才返回 complete。续跑沿用同一 run 的预算与授权关联，不另开安装主线。

## 2. 选择集成

显式参数优先于项目配置，其次是用户选择的默认 profile。使用简单注册表找到所选 agent、SDD、工具和客户集成。

读取对应版本的模板/能力映射，检查必需入口及依赖。不做通用依赖求解器，发现冲突或不支持项就报告。普通 update 不顺便升级所有工具。

没有 SDD 时可只配置工具、hooks 和自定义 skills；没有真实部署能力则不生成可执行发布入口。

## 3. 动态规划与生成

流程直接参考 OpenWiki 的“研究 → 提出计划 → 规范化任务 → 逐项补充研究/提交 → 接受后完成 → 汇总/恢复”，机制依据见[源码研究第 2–6 节](../../../research/2026-11-02-openwiki-analysis-generation.md)。本模块使用同一 AnalysisBackend 的 artifact-plan/artifact-content，不另造规范分析运行时。

ArtifactJob 对应其 PageJob 的用途，但目标是规范复用/补缺和 harness 接线：purpose 明确开发消费者，seedPaths 包含已有规范与代码起点，relatedArtifacts/instructions 只传当前主题所需上下文。seedPaths 不是读取边界，可以沿真实关系继续研究；复用已有文档的 job 只生成必要引用/接线，不重写原文。初步研究已完成的证据直接复用，未完成问题留给相关 job，不要求先穷尽全仓规范再开始规划。

Rigup 首版保持串行与私有候选，候选经校验和保存才算 job 完成；完成不等于已安装，最终仍经 Installer 预览/合并。模式识别的支持/反例/范围要求作为主题 instructions 与接受标准，不增加另一条调度主线。


1. 根据 Analyzer 2.0 的复用/缺口结果，先将已有规范绑定到文档标准第 4 节的 agent 入口、prepare/deliver 和已有检查使用点；保留原文/路径，不接管所有权，等效引用不重复追加。仅为缺口进入代码研究或补充正文。根据所选能力列出必需资产；固定机器配置及强制流程步骤由集成实现决定。
2. 模型根据 ProjectProfile 规划规范、模块级工程约定和流程 references（系统现状正文由 OpenWiki 负责，不进入本生成器清单），列 logicalId、目的、研究起点及相关产物，并按[文档标准](../2026-11-03-documentation-system-design.md)记录 consumer、required/reason、sourceRefs、acceptance，target/ownership 沿用安装意图。只为项目开发指南、所选 skills 和必要 references 规划正文，不增加文档类别注册表；已有内容足够时只引用。
3. 校验范围、重复项和必需项，并对 previousAssets 逐项交代继续维护、更新、提出退役或保留待处理；新旧逻辑身份变更按目标/选择器核对，不因改名漏掉旧项。形成普通串行清单，导航相互引用允许成环。
4. 每项使用局部上下文继续核实源码并生成候选，汇总/导航内容最后生成。
5. 按文档标准分别检查确定性格式/来源/能力引用/导航，以及正文语义充分性；必需正文不足时有限重做，耗尽不能用占位完成。保存候选后才标记该项完成。
6. 组装候选、显式客户模板与固定模板，检查旧库存无遗漏、引用及宿主自动加载点仍有效，生成完整 SetupPlan 后交给 Installer。这里检查候选 N；合并保留的 L 及最终接线由 Installer 第 2 节检查，候选通过不替代最终预览通过。

不同项目可以有不同内容和文档粒度。动态生成不是简单变量替换，但也不允许模型任意增加公开 skill、改审批政策或发明上游命令。

## 4. 小型生成缓存

私有缓存只需保存输入指纹、产物清单、每项 pending/done 状态、候选路径/摘要与错误。不是独立任务平台。

同一 run 的阶段/job、预算累计、授权关联和宿主请求也保存在此；runId 隔离候选，写入前取得总设计规定的项目执行锁。pending-host 只表示等响应，不增加已完成计数；CLI 退出前保存并释放锁，回传再取得锁并验证当前请求。已接受结果不重复消费响应，旧请求或另一轮响应不能推进当前 job。

先保存候选，再更新 done；重启时检查候选仍存在且匹配摘要。中断于两者之间可重新生成该项，接受少量重复工作，避免复杂的精确一次协议。

输入未变时复用完成项；输入或选择变化时保守重建生成清单。研究输入按 Analyzer 的所有权投影排除自身输出，补充读取沿用统一凭据过滤策略。缓存 key 包含读取策略版本；不能从旧缓存恢复未经当前策略过滤的材料。输入、有效选项及版本不变且候选缓存完整时，安装后再次 update 复用候选，不因新生成的文档或入口块重新调用模型；目标实际删改仍由 Installer 比较并保护。首版不承诺完整 Claims ledger、逐事实依赖图或运行中任意任务的精确失效。

旧库存核对与语义缓存分开：首次安装后 manifest 新登记本轮已接受资产时，按 logicalId/目标/选择器确定性对齐缓存清单，补其去向，不单因库存由空变为已安装就重做语义。新增旧项无法对齐、输入/来源变化或存在未核实规则时再按相关任务调查；已有请求仍绑定发出时的库存，变化后不能接收旧响应。

限制每项重试和总预算。必需项失败不能用占位文本完成计划；可选项按声明的缺失策略报告。

## 5. 输出与确定性部分

SetupPlan 列出目标文件/配置块、候选内容、安装/初始化任务、旧库存每项去向、明确移除项、来源和警告。显式本地模板按 Integrations 第 4 节确定性渲染；模板源字节和参数进入缓存/请求绑定，不能只看客户仓库源码指纹。

固定命令、机器字段和 gate 不交给模型自由渲染；生成脚本不依赖 installer 包。模板组装和路径映射在相同输入下稳定，模型正文不要求每次重跑相同。setup 只生成项目开发指南、所选 skills 和必要 references；需求/方案由研发 skills 在实际任务发生时维护，交付/反馈使用现有任务/MR/CI/平台记录，真实安装结果由 InstallReport 提供，不让模型预填。文档标准版本纳入缓存 key。

从 Analyzer 已核实的模式生成约定时，必须保留适用情形、范围、真实范例与例外/未知项；reference-only/needs-decision 不得升级为强制或全局规范。研究不足则按 Analyzer 2.1 补证，不用通用最佳实践填空。

入口只放通用命令与知识索引，模块规范和流程 references 按需引用，并保留权威来源/维护者。研发模板在现有 SDD/工单中承载目标、范围、验收、允许操作、预算/停止条件和接手人；按任务风险控制文档厚度，不另建协议引擎。风险政策来自客户，不按改动行数或模型自评自动放行。

只有显式停用或明确提出的托管文档退役才进入移除清单；省略、生成失败和输入未知不等于删除授权。

未更新或待处理的旧项沿用旧 ownership 和旧 B，不把本次遗漏当成注销或新基线。已知过时规则若仍被入口引用或宿主自动加载，必须修正/安全解绑；不能安全处理时计划保留阻塞，不返回可 apply 的成功计划。路径迁移在同一预览中表达创建与明确退役，用户改过的旧项继续走冲突规则。旧指南退役不授权删除其引用的非托管原规范。

## 6. 测试

验证单服务/monorepo 产生不同的合理清单、必需项未完成会阻止成功、重复 id/路径被拒、候选损坏需重做、输入变化不沿用旧结果、模板保留原生约束，以及源码和客户最终配置没有被生成过程修改。另验三类开发文档的职责边界及 setup 仅生成前两类必要内容、权威来源复用、无假 glossary/ADR/运行结果、局部模式不变成全局政策、无检查不声称强制、导航可达与必需正文充分性；真实生成另按兼容验收记录留证。

增加旧清单漏项、逻辑身份/路径变化、新反例使旧规则失效、自动加载旧规则及用户改过旧项的场景；不丢 ownership、不静默删除、不继续激活已知失效规则。用含“跳过 gate”或相反步骤的语义候选验证拒绝/重做，不能只验固定文字存在。模板真实消费、源变更失效及 MCP 合并按 Integrations 的扩展测试执行。
