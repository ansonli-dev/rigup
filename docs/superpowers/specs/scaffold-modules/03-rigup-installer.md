# Rigup Installer：安装与更新

所属：[总架构](../2026-11-02-rigup-design.md)。

## 1. 接口与职责

```typescript
preview(plan, resolutions?): Promise<Preview>
apply(previewId): Promise<InstallReport>
```

preview 读取实际目标、安装清单和基线，生成可审阅的最终差异；只写私有缓存。apply 校验该预览仍有效，再执行。目标前置摘要覆盖完整实际字节，不能复用已排除托管部分的研究输入指纹；即使生成缓存命中，仍检查用户对托管项的修改与删除。模型不会在 apply 时补写内容。CLI 可在研究前取得有界执行授权；生成后仍形成真实 preview，确定性核对路径/所有权、操作/版本、预算及目标前置摘要，范围匹配则自动绑定 previewId 并 apply，不追加问答。用户选择生成后审阅时才等待最终确认；越界/冲突只报告并停止，不以连续执行为由绕过检查。

规划与执行是同一模块的两个操作，合并规则和实际文件状态集中在此维护。

## 2. 预览与合并

读取 .rigup/manifest.json 和 baseline。对每个托管文件/配置块比较 B（原生成）、L（当前）和 N（新候选）：

- 不存在且无 B 的目标创建；有 B 而 L 消失视为用户删除，未经明确恢复不重建。L=N 不写；L=B 更新；N=B 保留用户修改。
- 三者不同只合并不相交变更，否则保留 L 并报告冲突。
- B 不可信或缺失且 L 已存在，不自动认领覆盖。

结构配置由集成实现合并具体键或标记块，保留无关字段与注释。无法安全处理时提供人工片段，不重写整份配置。

向导的逐项 adopt/restore/replace/remove 裁决作为可选私有 resolutions 传给 preview，绑定目标/选择器及当前完整摘要，重新预览后才允许 apply；摘要变化则裁决失效。接管、恢复或覆盖后的 baseline 仅保存生成内容 N，明确移除成功后注销 ownership，不把裁决当成永久覆盖授权。详见 [CLI 冲突交互](../2026-11-03-cli-interaction-design.md)。

移除仅处理明确列出的托管项。未修改可删除/解绑，用户改过则冲突保留；不自动卸载共享软件，不把遗漏当作删除指令。

preview 将旧 manifest 库存与 SetupPlan 的逐项去向对齐，漏项即拒绝。继续维护或保留待处理的项沿用可信旧基线/ownership；新基线目录须包含这些基线或保留仍有效的旧引用，不因本次未写而丢失。已知失效且仍可加载的规则必须完成修正或安全解绑，否则计划不可 apply；明确移除成功后才注销。单纯改 logicalId 不产生隐式接管/删除。

合并后以“最终写入内容＋保留的本地内容－明确移除项”构成只读虚拟项目，再核验配置可解析、必需原生入口/绑定、导航及本地引用可达。尚未执行但已核验 recipe 明确承诺的安装产物/原生入口可按计划依赖检查，标待实际 verify；无候选也无确定产出契约的目标不能算可达，OpenWiki 尚未生成的知识内容仍按原规则列待办。N 通过生成校验不代表合并结果通过：N=B 保留 L 或非交叠合并也可能破坏所选能力。只核验本次所选能力及其引用范围，不全面检查无关客户正文。确定性核验失败，或已知与必需流程/gates 冲突而不能沿用原接受结论时，保留 L、列出具体阻塞，不生成可执行预览；需要重新生成/语义判断的交回下一轮准备与生成，preview/apply 不调用模型。普通用户修改仍按 B/L/N 保留，不因为被修改就自动冲突或认领。apply 执行后、提交基线前再次核对上述接线及实际配置，项目检查红与接线被破坏分别处理。

## 3. 执行顺序

1. 确认当前 run 持有目标目录对应的执行锁，复核源码/选项、目标文件、工具版本及会话已结束的执行条件；独立 apply 入口先取得同一把锁。
2. 保存必要备份，执行明确选择的目录/Git 初始化及软件安装任务。
3. 写入所选配置、skills 和说明。
4. 初始化 OpenWiki/CodeGraph 等所选工具，核验配置/工具接入并运行已选择的项目检查，分别记录结果。
5. 接线必需步骤已完成时保存新生成基线及未更新项的旧基线引用，再原子替换 manifest，输出成功、待办与失败项，退出。

新基线写到独立的 baseline/<installId>/，manifest 切换前保留旧基线，避免清单写入失败时旧 B 已被覆盖。这是文件比较所需的备份，不是运行中的多版本交付包。

使用普通顺序任务列表，不需要安装 DAG、通用 ActionDriver 总线或多阶段 bundle 激活。安装、配置或初始化前置失败/未知时停止依赖动作，不执行依赖它的配置。仅项目测试/环境/eval 检查失败不撤销已成功接线，也不阻止保存其 manifest/baseline；InstallReport 保留失败，按 CLI 规则退出 1。所选必需初始化未完成则 pending，不能标整次安装完成；恢复先对账，不重复安装。

版本、路径和副作用范围都在预览中列明。安装命令不得暗中改未声明位置；上游工具无法限定或说明写入范围时，使用明确模板/人工方式。

### 3.1 外部写入与候选使用同一保护边界

- **项目文本：** 包管理/SDD/工具安装若要改项目 manifest、锁文件、agent 入口、hooks 或文档等客户文本，先通过确定性渲染/已核验的只读规划得到私有候选，再走 preview/B/L/N；私有暂存只保存候选，不为取得预览而执行安装或初始化。不能取得安全候选的已有目标不直接交给上游命令覆盖，提供复用或人工操作。
- **原生工具状态：** 不能提前得到精确正文的初始化，只在已授权的新空范围，或已核验为该工具管理且原生操作能保留客户内容的数据范围执行。recipe 明确其已有状态探测、保护依据、预期副作用与验证；无法区分工具状态与客户文件则阻止该操作。不改写 OpenWiki/CodeGraph 自有数据库或 AS-IS 实现，也不以备份替代覆盖前的保护。
- **目标重叠：** 外部操作不得直接写本次候选的托管范围；recipe 须拆出项目文本为候选、调整经核验的写入范围，做不到就报告人工接入。相同文件的独立选择器也需证明外部操作保留其他内容。每步执行前核对目标摘要/空目录/工具状态前置，执行后复核实际写入与配置摘要，未符合预览就停止后续并报告部分效果，不继续提交与实际不符的基线。

预览只展示目录边界的外部操作，还须展示该范围的保护方式及当前前置状态；“已声明路径”不自动授权覆盖已有资产。对无法限制的操作不先执行再靠恢复补救。

## 4. 失败与重试

私有进度记录保存任务 pending/done、文件前后摘要、备份位置及外部结果。重跑先检查实际状态；工具已安装或索引已建立则验证后复用。

可能产生写入/远端副作用的操作，必须先在用户应用状态目录原子持久保存未决记录，成功后才启动进程或发出请求；保存失败不得执行。复用既有操作数据，记录 run/操作身份、版本与非秘密参数摘要、目标/副作用范围、前置状态、授权引用及查询/对账线索，进程启动后补充可核实的进程身份。未决不表示动作一定发生，也不表示未发生。结果核实后先在该持久记录中保存终态，允许依赖动作按真实结果继续；关联的 manifest/持久进度已对齐后才清理记录，不能在请求返回成功但结果尚未保存时先清除。不明结果或结果保存失败仍须对账，普通缓存不充当唯一恢复依据。不要求新事务平台或跨系统精确一次。

超时的远端操作先查询实际结果，不能盲目再创建。无法可靠判断时停止并报告，不保证跨系统精确一次。

SIGKILL、崩溃或掉电后即使没有取消处理器运行，未决记录仍使续跑先对账；普通缓存丢失也一样。若中断发生在记录保存后、真正派发前，仍保守核对再决定；查询不了或无法确认旧写进程已退出时保持阻塞并交人工处理，不凭“无成功记录”重试。

多文件不是整体事务。失败可能留下部分成功配置；提供备份、Git diff 和下一步，重跑重新预览。不能自动 reset 用户工作区或强行回滚用户新修改。

manifest 失败时不把此前效果当作未发生。缓存仍在则对账后继续；缓存也丢失则重新扫描，有可信基线才合并，否则冲突保留。接受人工处理边界，不为它引入事务平台。

## 5. 锁与更新边界

锁以规范化目标目录区分，不依赖是否已有 Git，避免 git.init 时迁移状态。同一把执行锁覆盖研究、host 请求导出、生成和 apply，第二个活动进程直接报告占用，不先改缓存。host 待回传时保存 runId/请求/候选/累计预算和授权关联后释放锁，响应续跑重新取得并匹配；候选按 runId 隔离。跨 worktree、跨项目用户级配置和多机器并发不在首版保证内。

锁身份及未决写进程/远端动作记录置于用户应用状态目录，普通生成缓存仍在可丢弃缓存目录。Ctrl+C 只有确认写进程退出及本地写入结束才开放下次执行；无法确认则保存阻塞，后续取得锁前核对旧进程/实际结果。删除普通缓存不能清除阻塞或让未知远端动作自动重做。永久状态也不可用时先人工核对，不以缺记录证明动作未发生。

实际 apply 前结束会加载待改资产的 agent 会话，更新后重载配置。host 先完成只读研究及响应，用户退出相关会话后从独立终端按续跑命令执行；自动回传仍处于待更新宿主内时保存候选并退出 3，等待停会话条件成立，不热更新也不在长流程中弹问。Installer 不检测/管理研发 lease、不读取审批、不迁移在途任务。全局工具升级需显式选择，影响不明则保留并提示。

## 6. 报告与测试

配置写入、工具初始化、宿主加载和项目检查分别报告。需重启、无源码、缺凭据/环境是具体待办；测试失败不触发业务修复。

已有环境检查和 Agent eval 按选择运行，明确前置条件、耗时和副作用，不在 doctor 中暗中初始化业务环境。接线正确、项目可运行、软件测试通过、Agent 评估通过是不同结论；报告记录实际命令、版本/环境及结果引用。eval 缺失不阻塞无关安装项，也不被记为通过。

测试三方合并、注释保留、显式删除、外部编辑前置检查、重复安装、任务中断、manifest 写失败和远端超时。另验 CLI 不可用时已安装资产仍能运行。

另验允许目录内的初始化试图覆盖用户文件时执行前被拒、外部操作与候选重叠被拒/转候选、执行后摘要不符阻止提交基线、漏项旧资产不丢 ownership；N=B 保留 L/非交叠合并破坏引用或必需绑定时在预览阻止，普通局部改动仍保留；项目检查红仍保存成功接线并退出 1，重跑不重复副作用。故障注入覆盖未决记录保存失败、保存后未派发、请求已接收但未记结果、结果已知但 manifest 未保存，含强杀且清空普通缓存后的恢复；断言未决状态先于副作用可见、不重复创建、不提前解除阻塞。另验生成阶段并发不互改请求，以及真实 host-update 的先响应/退出/独立终端 apply/重载顺序。
