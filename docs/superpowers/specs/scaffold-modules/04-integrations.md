# Integrations：具体工具集成

所属：[总架构](../2026-11-02-rigup-design.md)。

## 1. 简单组织

使用随产品发布的注册表和普通实现文件：

```text
integrations/
  agents/       # Claude Code、Codex、OpenCode、Oh My Pi
  sdd/          # Superpowers、OpenSpec、Spec Kit
  tools/        # OpenWiki、CodeGraph、所选质量工具
  gitlab/       # CI、报告及客户系统入口
```

不是动态插件平台，不建立多层 ProviderFactory、能力总线和远程市场。不同类型可有各自的小接口，不强求一套继承体系。

集成 recipes、机器格式、命令和可执行脚本均由确定性代码/模板维护，按用户选择及已核实参数渲染。agent 可理解现有配置的语义并提出关联建议，但不能在 setup 时临时生成新的可执行 adapter。缺少适配就报告待接入。

## 2. 最小合作约定

集成按需提供 detect、prepare、verify，以及确需安装时的 setup 操作：

- detect 只读观察已有配置/版本。
- prepare 返回文件/配置意图、任务和说明，不改客户环境。
- setup 只由 Installer 调用，操作标识及参数可写入预览/缓存，不序列化可执行闭包。
- verify 分开说明配置存在、工具可用和宿主是否已加载。

通用数据是目标、内容/合并方法、运行依赖和支持版本。语义绑定用已知映射表，缺入口就报告，不生成万能动态解析规则。

每个 setup 明确区分“先渲染到候选的项目文本”和“外部操作写入的工具自有状态/新空范围”。declaredWrites 只是边界，不是对已有文件的覆盖许可；recipe 还要声明并核验已有目标的前置条件、用户内容保护方式、与候选重叠时的处理和执行后证据。无法证明安全的上游初始化改为复用或人工方式，执行准则见 Installer 第 3 节。生成区排除规则也由 recipe 提供，只排除核验过的输出，不排除同目录的用户输入。

## 3. 各类职责

Agent：处理原生 skills/入口/MCP 路径和格式，保留现有字段。四宿主分别测试；不能由“都是 JSON”推出兼容。

SDD：记录原生 skill/命令、产物位置和不可取消的前置条件。包装内置研发模板，支持一对多调用；不修改上游方法论或维护其研发状态。

OpenWiki/CodeGraph：软件安装、agent 注册、项目初始化分别执行。只调用官方入口，不改写其数据库、Claims 和索引。Pi 与 Oh My Pi 分别确认支持。

质量工具：复用已选 formatter/linter、hooks 和既有测试命令，不建设项目测试体系。pre-commit 检查实际暂存内容，pre-push 检查实际待推送内容；不让工作区未提交修复掩盖提交错误。

已有 Agent eval 可作为独立检查入口接入，数据集、评分器及门槛由团队提供；其结果不能与软件测试合并成一个通过标记。执行环境也只接线已有启动/就绪检查，不承担容器平台、测试数据或凭据系统建设。

GitLab：合并 CI include，正确保留失败退出码及测试报告，OpenWiki 更新避免自触发循环。日常 MR/CI/部署入口交给安装的 skills，installer 不充当代理服务。

身份、分支保护、受保护检查和生产审批仍由客户平台实施。安装不默认放宽权限；只有明确选择且具备相应授权时才配置，无法实施时列管理员待办，不用本地 hook 冒充强制治理。监控/工单集成可提供只读反馈入口，不新增后台监听器。

## 4. 客户本地扩展

支持本地 SKILL.md 目录和其 scripts/references/assets。普通 skill 可以直接安装，源内容归用户，不被重新生成。

需要参与内置流程时，用户选择插入位置/能力入口，并提供依赖及必要输入说明。第一版不自动发现远端包、不加载客户 JS/TS 安装插件、不暗中执行附带脚本。

命名冲突让用户明确选择。缺少凭据只保存环境引用和待办，不把密钥写进配置模板、文档或 diff。

**模板：** 除随 skill 原样复制的资源外，支持用户显式选择的本地文本模板及 `source/target/values` 映射。确定性渲染器只替换已声明的标量占位符（如 `{{projectName}}`），不执行表达式、helper、导入或附带脚本；缺参数/未知占位符报字段错误。首版用途是客户开发指南和所选自定义 skill 的 references/assets，不替换内置 skill 主流程/gates、脚本、hooks/CI 或机器配置，也不由模板新建 AS-IS 或 setup 时的变更文档。已有权威正文足够时继续引用，客户模板仍须有实际消费者。源路径在用户显式授权的本地读取范围内，目标在本次选定目录内，符号链接和命名冲突走现有校验。

例如选定 `customer/templates/review-notes.md.tmpl → docs/rigup/customer-review.md`，参数来自有效项目选择；Generator 渲染私有候选，固定 deliver 的评审步骤引用该页，再经 Installer 预览/合并。第一次与既有文件冲突不自动接管；模板或参数变化生成 N 与旧 B/L 比较。模板只提供客户上下文，不能指示跳过上游 gate；语义接受要求与其他正文相同。该最小路径不含模板编辑器、远端模板包或可执行安装插件。

**MCP：** 客户通过有效配置提供明确 server id、所选 agents、声明的本地命令/参数或远端 URL、环境变量引用；不用自由正文代替配置。比如本地 `customer-knowledge` server 的 `CommandSpec { executable, args, cwd, envRefs }` 经各宿主已核验的原生格式适配后，产生同一 server 的配置意图。未知 transport/宿主格式报不支持；同名 server 冲突走选择器合并，不覆盖其他 server。配置登记不启动服务；用户选择的连通性验证须在预览声明进程/网络副作用后才执行。无实际验证时只报 configured，不能报 connected。配置中不接受密钥值，日志/diff 过滤认证信息。

模板源、参数、MCP 的有效非秘密配置及适配版本进入缓存 key 和 host 请求绑定；源在项目外也不能遗漏摘要。项目外源只按显式选定的本地扩展输入读取，不放开 RepositoryReader 的项目根边界；进入模型的正文沿用同一脱敏投影，参数只取非秘密配置/环境变量引用，不展开凭据值。测试必须验证模板被实际 skill 引用使用、源/参数更新走三方保护、不能覆盖固定流程/越界，以及一个客户 MCP 输入在多宿主保留未知字段/已有 server 的真实配置合并；静态合并与真实宿主连接分别留证。

## 5. 支持与验证

按[上游核验标准](../../../compatibility/README.md)锁定精确版本、官方来源定位、命令/写入范围和副作用；未核验 recipe 不自动执行。官方接口核验、本地契约和真实运行分别留证，按[验收记录](../../../compatibility/verification.md)逐项更新。只承诺已经测试的版本组合。probe、prepare 无副作用，setup 使用结构化参数和明确路径，verify 返回真实证据。未知格式不强行改写，未知操作不以模型建议直接执行。

跨版本共享工具不会自动并行保留；需要保留旧环境时由用户选择项目级安装或延后升级。没有部署集成时不生成可执行发布入口。

按集成类型做少量契约测试，再选真实宿主/工具做最小冒烟。协议和模板存在不代表真实兼容矩阵已完成。

Task 4 先做所选组合的最小安装/发现/MCP 路径验证，再扩展渲染，及早暴露不可支持项；缺外部环境不阻止独立本地实现，pending 与需求缺口照常保留。
